# LIGHTNING 1.3

Двухэкранная Windows-игра с четырьмя режимами, двумя USB-джойстиками, Arduino Nano, автономной RFID-базой и локальной таблицей результатов.

## Режимы

- **Раунды** — общий набор полностью гасится, затем появляется новый.
- **Бесконечный набор** — каждое попадание заменяет общую кнопку новой.
- **Независимая гонка** — у каждого игрока собственные активные кнопки.
- **Дуэль** — одна общая кнопка, очко получает первый игрок.

После выбора режима выбирается длительность: 1, 2 или 3 минуты. Активные позиции на мониторах не показываются.

На каждой кнопке режима находится `?`. Она открывает описание и короткую анимацию механики на обоих экранах.

## Разблокировка режимов

Для нового профиля доступен только базовый режим «Раунды». Остальные режимы показываются с замком, а под названием LIGHTNING выводится сообщение «Сначала пройдите базовую игру».

После полного завершения базовой игры:

- RFID-профили обоих игроков получают постоянную отметку `basicCompleted`;
- при следующем сканировании этих браслетов дополнительные режимы доступны;
- если хотя бы один из двух игроков ещё не проходил базовую игру, дополнительные режимы остаются закрыты;
- для Player1/Player2 без браслетов разблокировка сохраняется до закрытия приложения.

Старые записи RFID-базы, в которых ещё нет поля `basicCompleted`, считаются новыми профилями.

## Модификатор X2

Работает в режимах «Бесконечный набор» и «Независимая гонка».

- прогресс считается по фактическим попаданиям, а не по увеличенному счёту;
- каждые 30 попаданий одна активная кнопка каждой стороны становится зелёной;
- первый игрок, взявший зелёную кнопку, убирает текущий бонус у соперника;
- все активные кнопки победившего игрока становятся зелёными на 5 секунд;
- каждое попадание в эти 5 секунд даёт два очка;
- попадания во время X2 приближают следующий бонус только на одно обычное попадание;
- на экране пульсируют счёт и надпись `X2`.

Настройки находятся в `config.json`:

```json
"modifiers":{
  "enabled":true,
  "modes":["replacement","independent"],
  "everyHits":30,
  "durationMs":5000,
  "multiplier":2
}
```

## Джойстики

При первом запуске игровой сессии:

1. нажмите любую кнопку синего игрока;
2. нажмите любую кнопку оранжевого игрока.

Назначение сохраняется до закрытия приложения. Это защищает от перестановки индексов двух одинаковых USB-плат после перезапуска Windows.

Кнопки 1–12 — позиции 1–12. Стик влево, вправо и вниз — позиции 13, 14 и 15. Поддерживаются кнопки Gamepad API и оси.

## Arduino Nano и две LED-линии

Установите библиотеку Adafruit NeoPixel и загрузите:

```text
arduino\Lightning_LED_Controller_Nano\Lightning_LED_Controller_Nano.ino
```

Подключение:

```text
D6 -> DIN синей ленты
D7 -> DIN оранжевой ленты
GND Arduino = GND обеих лент = GND блока питания
```

Каждая линия содержит 15 игровых позиций. Питание лент не должно проходить через вывод 5V Arduino.

Новый атомарный протокол:

```text
LEDS 0091 0842 1 3 0
CLEAR
TEST
```

Поля `LEDS`: маска синего, маска оранжевого, флаги X2, зелёная позиция синего, зелёная позиция оранжевого. Обе стороны задаются одной короткой командой.

Таблицы `BLUE_ORDER` и `ORANGE_ORDER` позволяют изменить физический порядок кнопок отдельно для каждой ленты.

## Автономная RFID-база

RFID-сканер должен определяться как USB-клавиатура и завершать UID клавишей Enter.

После назначения джойстиков:

1. сканируется браслет Player1;
2. для неизвестного UID вводится имя;
3. сканируется браслет Player2;
4. для неизвестного UID вводится второе имя.

Связи UID и имён хранятся локально. После 23:00 база очищается один раз за локальный календарный день. Новые карты, зарегистрированные после сброса, сохраняются до следующего дня.

Административные UID для ручной очистки задаются в `config.json`:

```json
"rfid":{
  "enabled":true,
  "dailyResetHour":23,
  "adminCardUids":["1234567890"],
  "scanTimeoutMs":80
}
```

Административную карту можно сканировать на экране ожидания браслета. Кнопка «Без браслета» оставляет имя Player1 или Player2.

## Запуск

Установите Node.js LTS и запустите:

```text
scripts\start-dev.bat
```

Для сборки portable EXE:

```text
scripts\build-exe.bat
```

## Проверки

`tests\engine.test.js` проверяет все четыре режима на 200 итерациях, блокировку повторного попадания, независимость сторон и подсчёт X2.
