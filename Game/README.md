# LIGHTNING

Двухэкранная Windows-игра с двумя USB-контроллерами по 16 кнопок, Arduino Nano, одной адресной лентой на 32 диода и интеграцией StriveX.

## Тестовый запуск и настройки техника

Запустите `scripts\start-interface-test.bat`. Gateway и сервер для тестов не требуются. В сворачиваемой панели просмотра есть кнопки тестовых браслетов; также можно набрать код и нажать Enter в любом из двух окон:

- `111` — игрок 1, `222` — игрок 2;
- `777` — техник: открывает настройки и завершает текущую игровую сессию;
- `999` — неизвестный браслет, `000` — ошибка связи с сервером.

В рабочем режиме вход выполняется настоящим браслетом сотрудника с ролью `technician` через обновлённый StriveX Gateway. Команды `777` и тестовые кнопки доступны при тестовом запуске. В общем Gateway добавлена поддержка режима техника для игры `lightning`.

В настройках выберите COM-порт Arduino, нажмите «Применить» и затем «Калибровать 32 кнопки». `auto` выбирает порт автоматически, `off` отключает подсветку, «Обновить» перечитывает список портов.

1. Загорается только диод 1. Нажмите и отпустите соответствующую физическую кнопку на любом из USB-контроллеров.
2. Загорается диод 2; повторите нажатие/отпускание. Для направления сдвиньте стик и верните его в нейтраль. Поддерживаются четыре направления и обычные кнопки.
3. Пройдите все 32 диода: 1–16 принадлежат игроку 1, 17–32 — игроку 2. Игрок определяется номером диода, независимо от контроллера, с которого пришло нажатие.
4. После отпускания последней кнопки карта автоматически сохраняется в `technician-settings.json` в каталоге данных приложения Electron (`%APPDATA%\lightning-attraction` по умолчанию). COM-порт сохраняется там же.

Удержание не переключает диод. Повторное назначение одной кнопки и одновременные нажатия не принимаются. «Отменить», отключение USB-контроллера или Arduino сохраняют предыдущую завершённую калибровку. Карточки в настройках позволяют отдельно проверить каждый диод; нажатия физических кнопок показывают счётчики.

Привязки используют ID контроллера и номер среди устройств с одинаковым ID. Если обе USB-платы имеют одинаковые ID, подключайте их в прежнем порядке и сохраняйте USB-порты: Gamepad API не предоставляет их серийные номера. Перед рабочей игрой необходима полная калибровка; клавиатурная имитация в тестовом режиме работает без неё.

## Интерфейс и просмотр экранов

В лобби используются общие правки Color Duel и TNT: заголовок «Уровни», списки на пять строк с прокруткой, перенос длинных названий и фиксированное положение кнопки «Старт». Подсказка «Прислони браслет» скрывается после сканирования двух игроков и возвращается при удалении игрока. Дублирующая строка выбранных параметров убрана; длительность и вариант остаются доступны справа.

После подтверждения Gateway «Старт» сразу запускает отсчёт — без приглашения «Входите» и дополнительного нажатия. Оба экрана показывают время текущего раунда; баланс оплаченного времени обрабатывается отдельно. Во время игры кнопка завершения скрыта. После GAME OVER, результатов и таблицы лидеров сессия игры закрывается, лобби очищается: для следующего раунда нужны новые сканирования двух браслетов. Оставшееся оплаченное время на сервере сохраняется.

Панель просмотра позволяет открыть правила, ожидание, отсчёт, игру, GAME OVER, результаты и лидеров; выбрать любой из десяти режимов; имитировать нажатия и запустить полный раунд. Тестовые рекорды, язык и прогресс браслетов хранятся отдельно от рабочих. Калибровка оборудования при обычном тестовом запуске остаётся общей с рабочей игрой.

`scripts\start-design.bat` (или `npm run design`) открывает два изменяемых окна рядом: вертикальный экран управления и горизонтальный экран игроков. CSS обновляется без перезапуска игры, изменения JS/HTML перезагружают страницы. Этот режим использует отдельный профиль `Lightning-Preview`; по умолчанию COM-порт отключён. При необходимости его можно включить в настройках техника этого профиля.

Для запуска из исходников проверена Node.js 22.22.0 x64. На новом ПК сначала должны установиться npm-зависимости, включая Electron. BAT-файлы `start-dev.bat`, `start-interface-test.bat` и `start-design.bat` проверяют их и выполняют установку автоматически; при первом запуске нужен интернет. Если запускаете через `npm run design` напрямую, сначала выполните в каталоге `Game` команду `npm install --include=dev --ignore-scripts=false`. Ошибка `Cannot find module 'electron'` означает отсутствие этих зависимостей, а не неправильную версию Node.js.

`npm run check:interface` проверяет обычный запуск, оба таймера, очистку пары, фиксированную геометрию лобби на четырёх разрешениях, экраны просмотра и изоляцию рекордов. Снимки сохраняются в `.tmp/interface-ui`.

## Режимы

- **Раунды** — общий набор полностью гасится, затем появляется новый.
- **Бесконечный набор** — каждое попадание заменяет общую кнопку новой.
- **Независимая гонка** — у каждого игрока собственные активные кнопки.
- **Дуэль** — одна общая кнопка, очко получает первый игрок.

После выбора режима выбирается длительность: 1, 2 или 3 минуты. Активные позиции на мониторах не показываются.

На каждой кнопке режима находится `?`. Она открывает описание и короткую анимацию механики на обоих экранах.

## Разблокировка режимов

Для нового профиля доступен только базовый режим «Раунды». Остальные режимы показываются с замком, а под названием LIGHTNING выводится сообщение «Сначала пройдите базовую игру».

После полного завершения базовой игры:

- RFID-профили обоих игроков получают постоянную отметку `basicCompleted`;
- при следующем сканировании этих браслетов дополнительные режимы доступны;
- если хотя бы один из двух игроков ещё не проходил базовую игру, дополнительные режимы остаются закрыты;
- для Player1/Player2 без браслетов разблокировка сохраняется до закрытия приложения.

Старые записи RFID-базы, в которых ещё нет поля `basicCompleted`, считаются новыми профилями.

## Модификатор X2

Работает в режимах «Бесконечный набор» и «Независимая гонка».

- прогресс считается по фактическим попаданиям, а не по увеличенному счёту;
- каждые 30 попаданий одна активная кнопка каждой стороны становится зелёной;
- первый игрок, взявший зелёную кнопку, убирает текущий бонус у соперника;
- все активные кнопки победившего игрока становятся зелёными на 5 секунд;
- каждое попадание в эти 5 секунд даёт два очка;
- попадания во время X2 приближают следующий бонус только на одно обычное попадание;
- на экране пульсируют счёт и надпись `X2`.

Настройки находятся в `config.json`:

```json
"modifiers":{
  "enabled":true,
  "modes":["replacement","independent"],
  "everyHits":30,
  "durationMs":5000,
  "multiplier":2
}
```

## Джойстики

Подключите две USB-платы. У каждой используются 12 кнопок и четыре направления (вверх/вниз/влево/вправо). Привязка всех входов к игровым позициям задаётся калибровкой техника и сохраняется после перезапуска. Фиксированной связи номера USB-кнопки с номером диода нет.

## Arduino Nano и одна LED-линия

Установите библиотеку Adafruit NeoPixel и загрузите:

```text
arduino\Lightning_LED_Controller_Nano\Lightning_LED_Controller_Nano.ino
```

Подключение:

```text
D6 -> DIN адресной ленты из 32 диодов
Диоды 1–16 -> игрок 1; 17–32 -> игрок 2
GND Arduino = GND ленты = GND блока питания
```

Прошивка V6 использует один вывод D6, 32 диода WS2812/NeoPixel, порядок GRB и 115200 бод. Требуется загрузить обновлённую прошивку: прежняя версия для двух линий D6/D7 с новой схемой не совместима. Питание ленты не должно проходить через вывод 5V Arduino.

Новый атомарный протокол:

```text
LEDS 0091 0842 1 3 0
CLEAR
TEST
CAL 1
CAL 32
```

Поля `LEDS`: маска синего, маска оранжевого, флаги X2, зелёная позиция синего, зелёная позиция оранжевого. Обе стороны задаются одной короткой командой.

`CAL N` гасит всю ленту и зажигает белым только физический диод N (1–32). `CLEAR` гасит ленту. Калибровка выполняется в игре, менять таблицы в прошивке не требуется.

## Автономная RFID-база

RFID-сканер должен определяться как USB-клавиатура и завершать UID клавишей Enter.

После назначения джойстиков:

1. сканируется браслет Player1;
2. для неизвестного UID вводится имя;
3. сканируется браслет Player2;
4. для неизвестного UID вводится второе имя.

Связи UID и имён хранятся локально. После 23:00 база очищается один раз за локальный календарный день. Новые карты, зарегистрированные после сброса, сохраняются до следующего дня.

Административные UID для ручной очистки задаются в `config.json`:

```json
"rfid":{
  "enabled":true,
  "dailyResetHour":23,
  "adminCardUids":["1234567890"],
  "scanTimeoutMs":80
}
```

Административную карту можно сканировать на экране ожидания браслета. Кнопка «Без браслета» оставляет имя Player1 или Player2.

## Запуск

Установите Node.js LTS и запустите:

```text
scripts\start-dev.bat
```

Для проверки без физических джойстиков используйте `scripts\start-interface-test.bat`. Тестовые клавиши подставляют позицию по слоту 0-5 в списке текущих активных кнопок (работает для режимов «Раунды», «Бесконечный набор», «Независимая гонка», «Дуэль»):

- синий: `Q W E R T Y`
- оранжевый: `B N M , . /`

Экран назначения контроллеров («нажмите любую кнопку») в этом режиме пропускается.

Для сборки portable EXE:

```text
scripts\build-exe.bat
```

## Проверки

`tests\engine.test.js` проверяет все четыре режима на 200 итерациях, блокировку повторного попадания, независимость сторон и подсчёт X2.

`npm run check` запускает линтер и все автоматические проверки, включая калибровку 32 входов, сохранение привязок, направления и отключение оборудования. `npm run check:technician` проверяет два настоящих окна Electron с имитацией USB и Arduino; снимки и изолированный тестовый профиль находятся в `.tmp/technician-ui`. Подключённое оборудование этот тест не использует.
